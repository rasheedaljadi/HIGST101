# توثيق استكشاف وبنية سكة دورة حياة الطلب المتقدمة (Advanced Dashboard Lifecycle Rail Implementation)

---

## 1. ملخص نتائج الاستكشاف المسبق

تطبيقاً للطلب القيادي، تم فحص وتوثيق البيئة البرمجية ومكونات لوحة الإدارة الحية قبل البدء بالتطوير:

| المطلب الاستكشافي | نتيجة الفحص الميداني والتوثيق |
| --- | --- |
| **نقطة اللوحة الحالية** | المتحكم [`DashboardController`](file:///e:/HIGESTO%20NEW1/higest/higest101/packages/Webkul/Admin/src/Http/Controllers/DashboardController.php)، العرض الرئيسية [`index.blade.php`](file:///e:/HIGESTO%20NEW1/higest/higest101/packages/Webkul/Admin/src/Resources/views/dashboard/index.blade.php)، ومجلد العرض المتقدم `advanced/index.blade.php`. |
| **مفتاح التفضيل [بسيط] [متقدم]** | محدد ومتوفر رسمياً عبر `toggleView()` والتفضيل المحفوظ في سشين السيرفر وعمود `admins.dashboard_view`. يُعتبر `simple` هو الخيار الافتراضي لجميع المستخدمين. |
| **مكونات Bagisto المتاحة** | دعم مكونات النوافذ المنبثقة [`<x-admin::modal>`](file:///e:/HIGESTO%20NEW1/higest/higest101/packages/Webkul/Admin/src/Resources/views/components/modal/index.blade.php) و Drawer وتكامل أيقونات SVG ونصوص الخطوط الرسمية. |
| **توقيع الخدمة `getOrderLifecyclePipeline()`** | تُرجع مصفوفة تراكمية تحتوي حصراً على المحطات الـ11 برمز كل محطة وعددها وقيمتها دون أي بيانات وهمية. |
| **صلاحيات الأمان (ACL)** | محمية بصلاحية `sales.orders` لإظهار مسار دورة الطلب والتفاصيل المفلترة. |
| **فجوة جودة البيانات (Unclassified Items)** | حساب فرق بنود الطلبات غير المكتملة أو التاريخية: الفرق بين إجمالي `order_items` و `order_item_lifecycle_stage_views` (مثال: 16 بنداً إجمالياً مقابل 10 بنود مصنفة = 6 بنود غير مصنفة). |

## 2. ترتيب أقسام العرض المتقدم

1. **القسم الأول**: الملخص التنفيذي القيادي (Executive Summary Cards).
2. **القسم الثاني**: **سكة دورة حياة الطلب الموحدة (Order Lifecycle Pipeline Rail)** - (القسم الجديد المضاف بحسب النمط المعتمد).
3. **الأقسام التالية**: صحة التوريد، تحليل المبيعات، والأرصدة حسب المصدر.
